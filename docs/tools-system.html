taskmng — Task Manager (TUI)

Entry: tm() in tools/system/taskmng/

An interactive terminal-based process manager similar to top/htop. Displays real-time process list with CPU and memory usage, and supports process control operations.

Architecture

The task manager is split across several files:

Core Types

taskmng_snapshot_t

A point-in-time capture of system state:

  • Hostname, kernel version, uptime
  • Load average (1, 5, 15 min)
  • Per-core and total CPU usage percentages
  • Total, available RAM and swap
  • GPU usage text (read from /sys or nvidia-smi output)
  • Array of up to TASKMNG_MAX_PROCESSES (512) processes
  • Process count and running count

UI state for the process list:

  • selected — Currently focused process index in visible list
  • scroll — Scroll position
  • frozen_pid — PID of frozen process for monitoring
  • filter_text, filter_input — Process filter
  • filter_editing — Whether filter prompt is active

CPU Tracking

The taskmng_runtime_t structure tracks CPU samples across refreshes to compute accurate delta-based CPU usage percentages. It samples /proc/stat for aggregate and per-core ticks, then computes the delta between consecutive reads.

Entry: uc() in tui.c

An interactive terminal user management tool for adding, deleting, and editing system user accounts. Runs as a full-screen TUI application using the shared ncurses-based TUI library. Requires root privileges for user modification operations.

Architecture — Three Modes

The tool operates in four distinct modes controlled by userc_view_t.mode:

ModeValueDescription
List0Default: browse existing users in a scrollable table
Add1Fill in fields for a new user account
Edit2Modify an existing user's properties (pre-filled from selected user)
Delete3Confirmation dialog before deleting a user

typedef struct {

Uses a fixed-size array rather than dynamic allocation — safe for the checked allocation conventions used elsewhere in the project.

User Data Loading — userc_load_users()

Located in users.c. Parses /etc/passwd line by line:

  1. Opens /etc/passwd with fopen(), reads each line with fgets() (max 512 bytes per line)
  2. Uses strsep() with : delimiter to extract the 7 standard POSIX passwd fields:
  3. Skips the password field (field 2, historically the hashed password, now typically x when using shadow passwords)
  4. UID and GID fields are converted from strings to integers via atoi()
  5. Strips trailing newline from the shell field
  6. Stops early if USERC_MAX_USERS (256) is reached
  7. Returns 0 on success, -1 if /etc/passwd cannot be opened

User Operations — users.c

Adding Users — userc_add_user()

Constructs a useradd system command via snprintf() into a 512-byte buffer:

useradd [-u UID] [-g GID] [-d HOME] [-s SHELL] USERNAME

Each option flag+value pair is emitted only if the corresponding field is non-empty. Executed via system(cmd) — relies on the system's useradd binary being present in PATH.

Deleting Users — userc_del_user()

Constructs and executes:

userdel -r USERNAME

The -r flag removes the user's home directory and mail spool. Uses system(cmd).

TUI Rendering — userc_draw_panel()

Located in tui.c. Renders different content depending on view->mode:

List Mode (mode 0)

  • Header: Column titles "USER", "UID", "GID", "HOME", "SHELL" in accent style
  • Scroll logic: Adjusts view->scroll so the selected item is always visible. Computes visible rows as height - 4 (reserving space for header, status line, and borders)
  • Rows: Each user is rendered as with field widths 16, 5, 5, 20, 16
  • Selection highlighting: Selected row uses TUI_STYLE_SELECTION (inverted colors), others use TUI_STYLE_NORMAL
  • Clip protection: All text is clipped to available width via clip_and_draw() helper using tui_clip_text()
  • Footer: A: Add | D: Delete | E: Edit | Q: Quit | W/S: Navigate list in muted style

Add/Edit Mode (mode 1/2)

  • Title: "ADD NEW USER" (mode 1) or "EDIT USER" (mode 2) in accent style
  • Five form fields displayed vertically with 2-line spacing:
    • Username: — text input (max 63 chars)
    • UID: — numeric text input (max 15 chars)
    • GID: — numeric text input (max 15 chars)
    • Home: — path text input (max 127 chars)
    • Shell: — path text input (max 63 chars)
  • Each field has a label on the left (12-char offset) and the current value on the right
  • Currently focused field (view->field_idx) uses TUI_STYLE_SELECTION, empty fields display (empty)
  • Footer: Enter: Next/Submit | Esc: Cancel | Backspace: Delete char

Delete Confirmation (mode 3)

  • Shows "DELETE USER?" in error style
  • Displays the username being deleted
  • Presents two buttons: [ YES ] (highlighted) and [ NO ] (normal)
  • Footer: Enter: Confirm | Esc/N: Cancel

Status Messages

The tool displays status messages in the bottom status bar:

  • "User Control: A add, D delete, E edit, Q quit." — default prompt on startup
  • "User added successfully." — after successful useradd (exit code 0)
  • "Failed to add user." — after failed useradd (non-zero exit)
  • "User deleted." — after successful userdel
  • "Failed to delete user." — after failed userdel
  • "User edit submitted (mock)." — edit mode is currently a placeholder (no usermod call yet)

Main Loop — uc()

  1. Initializes userc_list_t and userc_view_t (zeroed), loads users from /etc/passwd
  2. Initializes TUI via tui_init() — returns 1 on failure
  3. Frame loop (350ms poll interval via tui_poll_event):
    1. Gets terminal dimensions
    2. Clears and draws a bordered panel titled "User Control"
    3. Renders the current mode's UI via userc_draw_panel()
    4. Draws the status bar at the bottom
    5. Flushes via tui_end_frame()
    6. Polls for keyboard input
    7. Passes to userc_handle_key() — if not consumed, checks for Quit (Q/q/Esc in list mode)
  4. On quit: shuts down TUI via tui_shutdown(), returns 0

Limitations

  • Root required: useradd and userdel need superuser privileges
  • Edit mode: Currently only sets a status message — usermod is not called (TODO)
  • Password management: Not implemented — no passwd interaction
  • Group management: GID field is set but no group creation/deletion UI
  • Error granularity: Uses system() exit code only, no stderr capture
  • No confirmation on unsaved changes: Esc in add/edit mode discards without prompt

cvm — Current Video Mode

Source: tools/system/video/cvm.c (61 lines)

Entry: cv()

Displays the current video mode and screen resolution by querying the Linux framebuffer device (/dev/fb0) via ioctl() and /sys/class/graphics/fb0/modes.

Implementation

The tool is a single C function print_fb_info() plus main():

  1. Framebuffer detection: Attempts to open /dev/fb0 with open("/dev/fb0", O_RDONLY). If the device doesn't exist or can't be opened (e.g., no framebuffer driver, running in a VM without fbdev, or in text mode), prints "video mode: vga text mode (no framebuffer detected)" and returns.
  2. ioctl queries: Uses two Linux framebuffer ioctls on the opened fd:
    • FBIOGET_VSCREENINFO — fills struct fb_var_screeninfo with variable screen parameters:
      • xres, yres — current visible resolution (e.g. 1920×1080)
      • xres_virtual, yres_virtual — virtual buffer size (may be larger than visible for panning)
      • bits_per_pixel — color depth (e.g. 32 for ARGB8888)
    • FBIOGET_FSCREENINFO — fills struct fb_fix_screeninfo with fixed parameters:
      • id — driver name string (e.g. "efifb", "vesafb", "simpledrm", "bochs-drm")
  3. Sysfs max resolution: Opens /sys/class/graphics/fb0/modes and reads all lines. Each line is a mode descriptor in the format "WxHp-bpp@refresh" (e.g. "1920x1080p-32"). The tool iterates through all lines and stores the last one (which is typically the highest/available mode in the sysfs list). This provides information about what resolutions the framebuffer driver can support, beyond the current setting.
  4. Cleanup: Closes the framebuffer fd and returns.

Output Format

-------------------------------
video mode: efifb
current resolution: 1920x1080 (32 bpp)
virtual resolution: 1920x1080
available/max modes (sysfs): 1920x1080p-32

Usage

onetool cvm

Takes no arguments — simply probes the framebuffer subsystem and prints diagnostics.

Notes

  • No framebuffer: On systems without /dev/fb0 (e.g., modern systems using KMS/drm only, or SSH sessions), the tool reports "vga text mode (no framebuffer detected)". This is not an error — it's expected behavior on headless systems or when the framebuffer driver isn't loaded.
  • Driver names: Common values for finfo.id include "efifb" (UEFI GOP framebuffer), "vesafb" (VESA BIOS framebuffer), "simpledrm" (simpledrm driver), and "bochs-drm" (QEMU/Bochs virtual GPU).
  • KMS note: This tool uses the legacy fbdev interface, not KMS (kernel modesetting). Modern Linux graphics are moving toward KMS/drm, but fbdev is still widely available via the simpledrm or compatibility layers.
  • Sysfs modes: The /sys/class/graphics/fb0/modes file may not exist on all systems — in that case, only the current resolution from ioctl is shown.
