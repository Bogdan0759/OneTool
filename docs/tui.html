OneTool — TUI System

The OneTool TUI is defined entirely in tui.c (1336 lines). It provides an interactive terminal interface for browsing tools, configuring options, and launching tools with custom arguments.

Architecture Overview

The TUI is a state-machine driven, event-loop based interface with three screens:

  1. Tools screen — List all tools in a left panel with details/preview in the right panel
  2. Form screen — Shows a tool-specific form with fields (text, toggle, choice) for each argument
  3. Settings screen — Global settings: launch directory and theme palette configuration

Core State: onetool_tui_state_t

typedef struct {
    int screen;                                 // Current screen (0=Tools, 1=Form, 2=Settings)
    int selected_tool;                          // Index of selected tool
    int tool_scroll;                            // Scroll position in tool list
    int selected_field;                         // Currently focused form field
    int current_theme;                          // Active theme index (0-4)
    char status[160];                          // Status bar text
    char launch_dir[4096];                     // Working directory for tool launches
    onetool_form_t form;                          // Active tool form
    onetool_form_t settings_form;                  // Settings form
    const struct onetool_tool *active_tool;       // Tool currently being configured
    int settings_selected_field;                 // Settings field focus
    int settings_return_screen;                  // Screen to return to from settings
    taskmng_runtime_t taskmng_runtime;             // Task manager runtime state
    taskmng_snapshot_t taskmng_snapshot;           // Task manager snapshot
    taskmng_view_t taskmng_view;                   // Task manager view state
    userc_list_t userc_list;                       // User list
    userc_view_t userc_view;                       // User control view state
} onetool_tui_state_t;

Tool Forms

Each tool can have a custom form with up to TUI_MAX_FIELDS (16) fields. Forms are defined in load_embedded_tool_form() which contains a large if/else if chain mapping tool names to their form definitions.

Field Types

TypeEnumBehavior
TextONETOOL_FIELD_TEXTFree-form text input, supports typing and backspace. Values are passed as arguments with their flag prefix.
ToggleONETOOL_FIELD_TOGGLEBoolean on/off, toggled with Space. When on, the flag is emitted.
ChoiceONETOOL_FIELD_CHOICEMultiple preset options, navigated with Left/Right/Space. The selected value is emitted.

Form Field

typedef struct {
    char name[48];               // Internal field name
    char label[96];              // Display label
    char flag[24];               // CLI flag prefix (e.g. "-o", "--timeout")
    char value[256];             // Current value
    char default_value[256];     // Default value
    char placeholder[96];        // Placeholder hint
    char help[160];               // Help text (shown at bottom)
    int type;                       // Field type
    int option_count;               // Choice option count
    int choice_index;               // Currently selected choice
    onetool_choice_option_t options[16]; // Choice options
} onetool_form_field_t;

Field Flags

When building the command line for execution:

  • Text fields: if flag is non-empty, it is emitted before the value
  • Toggle fields: if value is "1"/"true"/"yes"/"on", the flag is emitted
  • Choice fields: same as text
  • Fields with flag = "@extra": the value is tokenized (supports quotes, escapes) and appended as-is

Special Tools: Task Manager & User Control

When taskmng or userc are selected on the tools screen, the right panel becomes an interactive live view instead of showing static tool details:

  • taskmng: Live process list refreshed each frame via taskmng_collect()/taskmng_refresh(). Keyboard events for process control are handled inline.
  • userc: User list displayed and managed directly in the right panel. Keyboard events for add/delete/edit are handled inline.

Themes

Five built-in themes (ocean, forest, amber, mono, custom) are defined in g_themes[]. Each theme is a tui_palette_t with 7 color slots.

Theme Cycling

Press T (uppercase) to cycle forward through themes. The cycle wraps around. When in settings, theme presets can be selected and individual colors can be changed, which switches to "custom" theme.

Settings Screen

The settings screen (open_settings()) provides:

  • Launch path: Working directory for tool execution (defaults to current directory)
  • Theme preset: Choice of ocean/forest/amber/mono/custom
  • Individual color fields: Background, Panel, Accent, Text, Muted, Success, Error — each with all 8 color options + default

Changes to individual colors switch to "custom" theme and apply live.

Tool Execution Flow

  1. run_active_tool() builds the argument list from form fields using build_tool_argv()
  2. TUI is shut down via tui_shutdown()
  3. The launch directory is changed if specified
  4. Tool is executed via onetool_run_tool()
  5. After tool exits, chdir() back to original directory
  6. Waits for Enter press before reinitializing TUI
  7. TUI is reinitialized with current theme

Token Parser

The tokenize_extra_args() function handles quoting and escaping for the "Extra args" field:

  • Single quotes '...': literal text, no interpretation
  • Double quotes "...": literal text
  • Backslash \: escapes the next character
  • Unmatched quotes return error (shown in status)
  • Whitespace separates tokens outside quotes

Preview System

At the bottom of form and tool screens, a preview line shows the command that would be executed. This is generated by build_preview_text() which runs the same build_tool_argv() function and formats the resulting arguments.
