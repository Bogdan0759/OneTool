OneTool — Network Tools

Three network tools: HTTP downloader (down), ICMP ping, and DHCP client (nsetup). All use raw sockets or the shared network library (libs/net).

Entry: dn() in cli.c

A curl-like HTTP client supporting GET, POST, and HEAD methods with TLS, custom headers, request body, and robots.txt etiquette.

Architecture

The down tool delegates all network operations to the shared library libs/net:

  • net_parse_http_url() — URL parsing into host/port/path/TLS flag
  • net_conn_open() — TCP connection with optional TLS upgrade
  • net_http_send_request() — HTTP/1.1 request construction
  • net_http_read_response() — Response header parsing + body reading (chunked, content-length, connection-close)
  • net_robots_is_allowed() — robots.txt fetch and parse

Request Structure — down_request_t

typedef struct {
    char *url;              // Target URL (e.g. "https://example.com/index.html")
    char *method;           // HTTP method: GET (default), POST, HEAD
    char *host;             // Hostname extracted from URL (e.g. "example.com")
    char *port;             // Port extracted from URL ("80" or "443" by default)
    char *path;             // URL path + query (e.g. "/index.html?q=1")
    char *body;             // Request body for POST requests
    char *output_path;      // File path to save response (NULL = stdout)
    char *headers[64];   // Custom header strings (array of malloc'd copies)
    int header_count;       // Number of custom headers
    int timeout_sec;        // Connection timeout in seconds (default 10)
    int verbose;            // Print diagnostics to stderr
    int quiet;              // Suppress status lines on stderr
    int use_tls;            // 1 if HTTPS (TLS) should be used
    int ignore_robots;      // Skip robots.txt check
} down_request_t;

CLI Parsing — down_parse_cli()

Located in core/parse.c (175 lines). Implements iterative argument processing:

  • Flags parsed: -v (verbose), -q/--quiet, -o (output file), -X (method), -H (custom header, up to 64), -d (body), --timeout (1-3600 seconds, validated with strtol), --ignore-robots, --help
  • Method auto-detection: If no -X is given but -d (body) is provided, method defaults to POST. Otherwise defaults to GET.
  • Method normalization: Converts method string to uppercase via toupper()
  • URL parsing: Delegates to down_parse_url() which calls net_parse_http_url(), storing the extracted host, port, path, and TLS flag into the request struct
  • Memory management: Uses internal down_strdup() wrapper. All strings freed by down_request_free()
  • Error handling: Prints errors to stderr (unknown option, missing value, too many headers, OOM). Returns 0 on success, 1 on error, 2 for help (don't run).

Request Execution — down_run()

Located in core/send.c (88 lines). The HTTP request lifecycle:

  1. Status header: If not quiet, prints down: METHOD scheme://host:port/path to stderr
  2. Robots check: Calls down_check_robots() which calls net_robots_is_allowed(). If the fetch fails (network error), the check is silently skipped. If robots.txt explicitly disallows the path, prints down: blocked by robots.txt /path and returns error.
  3. Connect: Opens TCP connection via net_conn_open() with the configured timeout. If verbose: prints down: connected to host:port (http/https)
  4. Send request: Calls net_http_send_request() with method, path, host, custom headers array, body, and user-agent "onetool-down/0.2"
  5. Read response: Calls net_http_read_response() which writes the response body to the output file/stdout, parses status code and content-length
  6. Status report: When not quiet, reports HTTP status code + body bytes. If output file was used, reports where the response was saved.
  7. Cleanup: Closes the connection and returns 0 on success.

Robots.txt Checking — down_check_robots()

Located in core/robots.c (28 lines). Calls net_robots_is_allowed() from libs/net with user-agent "onetool-down". If the robots.txt fetch itself fails (e.g., DNS resolution fails, connection refused), the check is silently skipped to avoid breaking requests when the server is unreachable for the initial fetch. If the response explicitly disallows the path, the download is aborted with an error message.

Entry Point — main() in cli.c

  1. Calls down_parse_cli() — returns 0=run, 1=error, 2=help
  2. If output path specified: opens file with fopen(path, "wb") — prints error and returns 1 on failure
  3. Calls down_run() with the request and output FILE*
  4. If output file was opened, closes it via fclose()
  5. Frees the request struct via down_request_free() — frees all malloc'd string fields and custom headers

Usage

onetool down [options] 

Options:
  -o file           Output to file instead of stdout
  -X method         HTTP method (GET, POST, HEAD)
  -d body           Request body for POST
  -H header         Add custom header (can repeat, max 64)
  --timeout sec     Connection timeout (default 10, max 3600)
  --ignore-robots   Skip robots.txt check
  -v                Verbose (print diagnostics to stderr)
  -q, --quiet       Quiet mode (suppress status lines)
  -h, --help        Show help

Examples

# Simple GET
onetool down https://example.com

# Save to file
onetool down -o index.html https://example.com

# POST with body
onetool down -X POST -d "name=test" https://httpbin.org/post

# Verbose with custom headers
onetool down -v -H "Authorization: Bearer token" https://api.example.com/data

# HEAD request with timeout
onetool down -X HEAD --timeout 5 https://example.com

Status Output

When not in quiet mode, the tool prints to stderr:

down: HTTP 200 OK, 1256 bytes

Or with -o file:

ping — ICMP Ping

Source: tools/network/ping/cli.c (230 lines, single file)

Entry: pg()

A self-contained ICMP echo client (ping) implemented entirely from scratch with raw sockets. Requires root or CAP_NET_RAW for raw socket access.

Architecture

The entire ping tool is a single C file with no external library dependencies beyond standard POSIX headers. It uses:

  • socket(AF_INET, SOCK_RAW, IPPROTO_ICMP) — raw IPv4 ICMP socket
  • getaddrinfo() — hostname resolution (IPv4 only)
  • sendto() / recvfrom() — raw packet I/O
  • poll() — per-packet timeout with millisecond precision
  • gettimeofday() — microsecond-precision timestamps for RTT calculation

Options Structure — ping_opts_t

typedef struct {
    const char *host;       // Target hostname or IP
    int count;               // Number of echo requests (default 4, max 1000000)
    int timeout_ms;          // Per-packet timeout in ms (default 1000, max 600000)
    int payload_size;        // Payload size in bytes (default 56, max 1400)
    double interval_sec;     // Interval between packets (default 1.0, min 0.01, max 3600)
    int quiet;               // Print only final summary
} ping_opts_t;

CLI Parsing — parse_opts()

Parses options from argv[] into ping_opts_t. Uses value helpers with range validation:

  • parse_int() — uses strtol(), validates range [min_v, max_v], rejects trailing garbage
  • parse_double() — uses strtod(), validates range [min_v, max_v]
  • Flags: -c (count, 1-1000000), -W (timeout ms, 1-600000), -s (payload size, 0-1400), -i (interval, 0.01-3600.0), -q/--quiet, -h/--help
  • Defaults: count=4, timeout=1000ms, payload=56, interval=1.0, quiet=0

ICMP Packet Construction

  1. Packet buffer: 1500-byte buffer (max Ethernet MTU). Total packet size = sizeof(icmphdr) + sizeof(timeval) + payload_size
  2. ICMP header fields:
    • icmp->type = ICMP_ECHO (8) — echo request
    • icmp->code = 0
    • icmp->un.echo.id = htons(pid & 0xFFFF) — process ID to match replies
    • icmp->un.echo.sequence = htons(seq) — sequence number 1..count
  3. Timestamp embedding: Immediately after the ICMP header, gettimeofday(&send_tv) is stored — this is used later to compute RTT by comparing with the reception timestamp
  4. Payload fill: Remaining bytes are filled with a predictable pattern (i & 0xFF)
  5. Checksum: Computed via the standard Internet checksum algorithm on the entire packet (header + timestamp + payload) using icmp_checksum()

Send and Receive Loop

For each sequence number from 1 to count:

  1. Build packet as described above
  2. Send: sendto(sock, packet, pkt_len, 0, &dst, sizeof(dst)) — increments tx counter. On send error: prints ping: sendto failed: strerror and continues to next sequence
  3. Poll: poll(&pfd, 1, timeout_ms) — waits for data on the raw socket:
    • Timeout (0): Prints request timeout icmp_seq N
    • Error (<0): Handles EINTR (ignore), otherwise prints poll error
    • Data available (>0): Calls recvfrom() into a 2048-byte buffer
  4. Reply parsing: Validates the received packet is at least sizeof(iphdr) + sizeof(icmphdr) bytes. Parses the IP header to get IHL (IP header length, typically 20 bytes). Extracts the ICMP header from recvbuf + ihl:
    • Checks ri->type == ICMP_ECHOREPLY (0)
    • Checks ntohs(ri->un.echo.id) == pid_id — matches our process ID to avoid picking up other ping replies
    • Reads embedded timestamp from recvbuf + ihl + sizeof(icmphdr)
    • Computes RTT via ms_since(&sent_in_pkt, &recv_tv) — difference in microseconds converted to milliseconds
    • Updates min/max/sum RTT statistics, increments rx counter
    • If not quiet: prints N bytes from IP: icmp_seq=N ttl=N time=XXX.XXX ms
  5. Inter-packet delay: If not the last packet, calls usleep(interval_sec * 1000000)

Statistics Summary

After the loop:

  • Prints the target hostname/IP
  • If any packets were transmitted: prints N packets transmitted N received X.X% packet loss
  • If any replies were received: prints rtt min/avg/max = X.XXX/X.XXX/X.XXX ms
  • Returns 0 if at least one reply was received, 1 otherwise

ICMP Checksum — icmp_checksum()

static unsigned short icmp_checksum(const void *data, size_t len) {
    const unsigned short *p = data;
    unsigned int sum = 0;
    while (len > 1) {
        sum += *p++;
        len -= 2;
    }
    if (len == 1)
        sum += *(const unsigned char *)p;
    while (sum >> 16)
        sum = (sum & 0xFFFF) + (sum >> 16);
    return ~sum;
}

This is the standard 16-bit one's complement Internet checksum (RFC 1071). Used by ICMP, IP, TCP, and UDP. The algorithm sums 16-bit words, folds carries, and returns the bitwise complement.

RTT Calculation — ms_since()

static double ms_since(const struct timeval *start, const struct timeval *end) {
    double sec = (double)(end->tv_sec - start->tv_sec);
    double usec = (double)(end->tv_usec - start->tv_usec);
    return sec * 1000.0 + usec / 1000.0;
}

Computes the difference between two struct timeval timestamps in milliseconds as a double (microsecond precision). This handles the full range of possible RTT values without overflow.

Error Handling

  • Permission: If socket() fails with EPERM or EACCES, prints ping: raw socket requires root or CAP_NET_RAW — a helpful message for users who forgot sudo
  • DNS resolution: If getaddrinfo() fails, prints ping: cannot resolve host NAME
  • Payload overflow: If computed packet size exceeds 1500 bytes, prints error and exits
  • Invalid options: All option values have min/max bounds checking with descriptive error messages

nsetup — Network Setup (DHCP)

Entry: ns() in tools/network/nsetup.c

A minimal DHCP client that can bring up a network interface and obtain IPv4 configuration via DHCP. Implements the DHCP protocol from scratch (no external DHCP library).

Implementation Details

The DHCP client implements the full DORA (Discover, Offer, Request, Acknowledge) sequence:

  1. Discover: Broadcasts a DHCPDISCOVER packet to find available DHCP servers
  2. Offer: Waits for DHCPOFFER from a server containing proposed IP configuration
  3. Request: Sends DHCPREQUEST to formally request the offered lease
  4. Acknowledge: Waits for DHCPACK confirming the lease

Packet Format

The DHCP packet is defined as a packed C struct matching the RFC 2131 format:

typedef struct __attribute__((packed)) {
    uint8_t op;            // Message op code
    uint8_t htype;          // Hardware address type
    uint8_t hlen;           // Hardware address length
    uint8_t hops;           // Hops
    uint32_t xid;           // Transaction ID
    uint16_t secs;          // Seconds elapsed
    uint16_t flags;         // Flags
    uint32_t ciaddr;        // Client IP
    uint32_t yiaddr;        // Your IP
    uint32_t siaddr;        // Server IP
    uint32_t giaddr;        // Relay agent IP
    unsigned char chaddr[16]; // Client hardware address
    unsigned char sname[64];  // Server host name
    unsigned char file[128];   // Boot file name
    uint32_t cookie;         // Magic cookie (0x63825363)
    unsigned char options[312]; // DHCP options
} dhcp_packet_t;

Network Configuration Applied

After obtaining a DHCP lease, the tool applies:

  • Interface brought up (SIOCSIFFLAGS with IFF_UP)
  • IP address (SIOCSIFADDR)
  • Netmask (SIOCSIFNETMASK)
  • Broadcast address (SIOCSIFBRDADDR)
  • Subnet route via SIOCADDRT
  • Default gateway via SIOCADDRT with RTF_GATEWAY
  • /etc/resolv.conf updated with DNS servers and search domain

Usage

onetool nsetup [interface]

Without arguments, lists available interfaces and prompts selection.
Requires root.

Example

# onetool nsetup eth0
waiting for DHCP offer...
waiting for DHCP ack...

network ready on eth0
  ip:      192.168.1.100
  netmask: 255.255.255.0
  gateway: 192.168.1.1
  dns:     8.8.8.8, 8.8.4.4

Interface Discovery

The tool uses getifaddrs() to enumerate all network interfaces, reads operstate from /sys/class/net/*/operstate, and shows MAC addresses via SIOCGIFHWADDR. Interfaces with IFF_LOOPBACK flag are excluded from DHCP.
