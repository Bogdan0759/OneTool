OneTool — Filesystem Tools

Six tools for inspecting files and filesystems. All are single-file C programs (except size which uses the shared ELF library).

lastmod — Last Modification Time

Source: tools/filesystem/lastmod.c (30 lines)

Entry: lm()

Prints the last modification time (mtime) of a file in human-readable format.

Implementation

  1. Calls stat(input_file, &file_stat) on the provided path
  2. Reads st_mtime (a time_t) from the stat result
  3. Formats with ctime(&last_mod_time) — produces output like last modification time of /etc/hosts is: Thu Apr 15 12:00:00 2025

Error handling: If stat() fails (file not found, permission denied, etc.), prints stat: and returns 1.

Usage: onetool lastmod

Example:

$ onetool lastmod /etc/hosts
last modification time of /etc/hosts is: Thu Apr 10 14:23:45 2025

Note: unlike the classic Unix stat command, this tool always uses ctime() and supports a single file argument only.

exec — Execute File

Source: tools/filesystem/exec.c (53 lines)

Entry: ex()

Runs a file directly (via execv()) or through a specified interpreter. Replaces the current process — no fork, no return on success.

Implementation

  1. Argument parsing: Iterates through argv[] looking for -i interpreter followed by the path argument. Rejects extra arguments.
  2. Direct execution: If no interpreter given, builds exec_argv = [path, NULL] and calls execv(path, exec_argv).
  3. Interpreter execution: If interpreter given, builds exec_argv = [interpreter, path, NULL] and calls execv(interpreter, exec_argv) — effectively running interpreter path.
  4. Error handling: If execv() returns, prints exec failed (): and returns 1. Common failures: ENOENT (file not found), EACCES (no execute permission), ENOEXEC (bad binary format).

Usage: onetool exec [-i interpreter]

OptionDescription
pathPath to the program or script to execute
-i interpreterRun path through this interpreter (e.g., -i python)

Examples:

onetool exec ./a.out
onetool exec script.sh -i /bin/bash
onetool exec script.py -i python3

Note: This is NOT a subprocess spawner. It replaces the OneTool process with the target program via execv(). The exec family of functions does not search PATH — full paths are required. For PATH-based lookup, use full paths like /usr/bin/python3.

fsinfo — Filesystem Information

Source: tools/filesystem/fsinfo.c (81 lines)

Entry: fi()

Inspects a filesystem path and prints detailed filesystem and inode information using statvfs() and /proc/mounts parsing.

Implementation

  1. statvfs: Calls statvfs(path, &vfs) to get filesystem statistics: total/available/free inodes.
  2. Mount point resolution: Opens /proc/mounts via setmntent(), resolves the given path to an absolute path via realpath(), then iterates over mount entries to find the longest matching mount point (most specific match). Extracts:
    • mnt_fsname — the block device (e.g., /dev/sda1)
    • mnt_type — the filesystem type (e.g., ext4, tmpfs, btrfs)
  3. Inode calculation: Computes used inodes = f_files - f_ffree, usage percentage = (used * 100) / total (if total > 0).

Output fields:

FieldSource
fs nameFilesystem type from /proc/mounts (e.g., ext4, tmpfs)
inodes totalstatvfs.f_files
inodes usedf_files - f_ffree
inodes availablestatvfs.f_favail
inodes usagePercentage: (inodes_used * 100) / inodes_total
inodes nameBlock device from /proc/mounts

Usage: onetool fsinfo

Example:

$ onetool fsinfo /
fs name: ext4
inodes total: 12345678
inodes used: 234567
inodes available: 11000000
inodes usage: 2%
inodes name: /dev/nvme0n1p2

Note: Unlike the old version shown in overview.html (which used stat() for file info and statvfs() for block counts), the current implementation focuses exclusively on inode statistics and mount info from /proc/mounts.

fsize — File Size

Source: tools/filesystem/fsize.c (99 lines)

Entry: fz()

Prints the size of a file in bytes or in human-readable units. Supports multiple file arguments.

Implementation

  1. Human-readable formatting: The format_human() function uses a 1024-based unit progression: B → KB → MiB → GiB → TiB → PiB. Uses double division and snprintf() with %.1f for fractions.
  2. File checking: Uses stat() and checks S_ISREG(st.st_mode) — rejects non-regular files with error: is not regular file.
  3. Multi-file support: Accepts multiple file arguments. Each file gets its own line. Continues processing remaining files on error (best-effort).

Output format:

  • Raw mode (-h omitted): 1234 filename
  • Human mode (-h): 1.2 KiB filename

Usage: onetool fsize [-h] [...]

OptionDescription
-h, --humanPrint size with binary unit suffixes (B, KiB, MiB, GiB, TiB, PiB)
--helpShow help text

Examples:

$ onetool fsize /etc/hosts
234 /etc/hosts
$ onetool fsize -h /etc/hosts /bin/bash
234 B /etc/hosts
1.4 MiB /bin/bash

size — ELF Section Sizes

Source: tools/filesystem/size.c (161 lines) + libs/elf/

Entry: sz()

Analyzes an ELF binary and prints section sizes. Supports two output formats (Berkeley and SysV). Uses the shared ELF parsing library (ot_elf_parse()) to read section headers.

Implementation

  1. File reading: Uses a custom read_file() that reads the entire file into a dynamically growing buffer (starts at 16KB, doubles as needed). Handles EINTR during reads.
  2. ELF parsing: Delegates to ot_elf_parse() from libs/elf — validates ELF magic, class (64-bit only), endianness (little-endian only), version.
  3. Section classification (Berkeley mode): The add_alloc_section() helper iterates all sections with SHF_ALLOC flag and classifies into:
    • text: sections without SHF_WRITE and not SHT_NOBITS (code + read-only data combined)
    • data: sections with SHF_WRITE and not SHT_NOBITS (initialized data)
    • bss: sections with SHT_NOBITS (zero-initialized data)
  4. Berkeley output: Prints a header line once, then for each file: text data bss dec hex filename.
  5. SysV output: Prints per-section details: section name, size in decimal, address in hex, and a Total line.

Usage: onetool size [-A|-B] [...]

OptionFormatDescription
-B (default)Berkeley summaryShows text, data, bss, and total sizes in a compact line per file
-ASysV detailedShows every section with name, size, and address

Examples:

$ onetool size /bin/ls
   text    data     bss     dec     hex filename
 123456   7890    1234  132580   205e4 /bin/ls

$ onetool size -A /bin/ls
/bin/ls  :
section                           size              addr
.interp                            28      0x318
.note.gnu.build-id                 36      0x338
.note.ABI-tag                      32      0x35c
.gnu.hash                          48      0x380
.dynsym                           240      0x3b0
...
Total                             94320

nm — ELF Symbols

Source: tools/filesystem/nm.c

Entry: nm()

Prints symbols from an ELF symbol table. Mimics classic Unix nm(1) in spirit.

Implementation

  1. Parses the ELF file using ot_elf_parse() from libs/elf
  2. Locates the SHT_SYMTAB section (symbol table)
  3. Reads each symbol entry (24 bytes each for ELF64): name (via strtab offset), value (8 bytes), size (8 bytes), info (1 byte: bind+type), other (1 byte), shndx (2 bytes)
  4. Classifies by ELF64_ST_TYPE (STT_FUNC, STT_OBJECT, etc.) and ELF64_ST_BIND (STB_GLOBAL, STB_LOCAL, STB_WEAK)
  5. Determines symbol visibility based on shndx: SHN_UNDEF = undefined, SHN_ABS = absolute, SHN_COMMON = common
  6. Output formatting: uppercase letter = global, lowercase = local

Output format: address type symbol_name where type is one of:

  • T / t — Text (code) section symbol
  • D / d — Data section symbol
  • B / b — BSS symbol
  • U — Undefined (imported from another object)
  • ? — Unknown/unclassified

Upper case = global, lower case = local.

Usage: onetool nm [-a|-g|-u]

OptionDescription
(none)Show all defined symbols
-aInclude empty and debug symbols
-gExternal (global) symbols only
-uUndefined symbols only

Example:

$ onetool nm -g ./main.o
0000000000000000 T main
0000000000000030 T helper_function
         U printf
         U malloc

cat — Print Files

Source: tools/filesystem/cat.c (80 lines)

Entry: cat()

Reads files sequentially and writes them to stdout. Supports line numbering and reading from stdin (via - argument or when no files are given).

Implementation

  1. Option parsing: Supports -n/--number (line numbering) and --help. Unknown options return error.
  2. File detection: If argument is "-", reads from stdin via print_stream(stdin, ...). Otherwise opens file with fopen(path, "r") — prints error: path: strerror on failure and continues to next file.
  3. Stream reading (print_stream): Reads character-by-character with fgetc(). If -n is active and at line start, prints %6d\t with incrementing line number (starting at 1). Tracks line start state via at_line_start flag (becomes true when ch == '\n').
  4. Default stdin: If no file arguments given, reads from stdin (like classic cat without arguments).
  5. Error handling: Checks ferror(fp) after the read loop — prints read error if set.

Usage

onetool cat [options] [file...]

Options:
  -n, --number   Number output lines
  --help         Show help

If no file is given, reads from stdin.
Use "-" to read from stdin explicitly among files.

Examples

$ onetool cat /etc/hostname
myhost

$ onetool cat -n /etc/hosts
     1	127.0.0.1 localhost
     2	::1       localhost

$ echo "hello" | onetool cat -n
     1	hello

$ onetool cat - /etc/hosts  # stdin then file

free — Memory Usage

Source: tools/filesystem/free.c (118 lines)

Entry: free()

Displays system memory usage by parsing /proc/meminfo. Shows total, used, free, shared, buff/cache, and available memory for both RAM and swap. Supports multiple output unit formats.

Implementation

Memory Info Parsing — read_meminfo()

  1. Opens /proc/meminfo with fopen("/proc/meminfo", "r") — returns error if unavailable
  2. Reads each line with fscanf(fp, "%63[^:]: %" SCNu64 " %15s\n", key, &value, unit) — extracts key name (up to 63 chars before :), numeric value, and unit string ("kB")
  3. Multiplies all values by 1024 to convert from kilobytes to bytes
  4. Matches keys: MemTotal, MemFree, MemAvailable, Buffers, Cached, SwapTotal, SwapFree
  5. Returns 1 (error) if info->total == 0 (no MemTotal found)

Computed Fields

  • buff_cache = Buffers + Cached
  • used = MemTotal - MemFree - buff_cache (clamped at 0 via ternary)
  • swap_used = SwapTotal - SwapFree

Unit Conversion

Supports five output modes via divisor:

FlagDivider
-b1 (bytes)
-k (default)1024 (KiB)
-m1,048,576 (MiB)
-g1,073,741,824 (GiB)
-hHuman-readable (auto-selects B/KiB/MiB/GiB/TiB)

Human Formatting (format_value)

In human mode: divides by 1024 repeatedly (B → KiB → MiB → GiB → TiB) and formats with %.1f and unit suffix. In raw mode: divides by the chosen divisor and prints integer.

Output Format

              total        used        free      shared  buff/cache   available
Mem:         8123456     1234567      3456789           0     2345678      6789012
Swap:        2097152      123456      1973696           0           0           0

Each column is 12 characters wide, right-aligned.

Usage

onetool free [-b|-k|-m|-g|-h] [--help]

Options:
  -b            bytes
  -k            KiB (default)
  -m            MiB
  -g            GiB
  -h, --human   human readable
  --help        show help

Examples

$ onetool free
              total        used        free      shared  buff/cache   available
Mem:         8123456     1234567     3456789           0     2345678     6789012
Swap:        2097152      123456     1973696           0           0           0

$ onetool free -h
              total        used        free      shared  buff/cache   available
Mem:          7.8GiB      1.2GiB      3.3GiB           0      2.2GiB      6.5GiB
Swap:         2.0GiB      120.6MiB    1.9GiB           0           0           0

ls — List Directory

Source: tools/filesystem/ls.c (215 lines)

Entry: ls()

Lists directory contents. Supports short format (filenames only), long format (-l with permissions, owner, size, date), hidden files (-a), and human-readable sizes (-h). Defaults to current directory if no path given.

Implementation

Option Parsing

  • -a/--all — include dotfiles (entries starting with .)
  • -l/--long — detailed listing with permissions, owner, group, size, mtime
  • -h/--human — human-readable sizes (only with -l)

Directory Listing — list_dir()

  1. Opens the directory with opendir(path) — prints error on failure
  2. Iterates with readdir(dir) — skips hidden files (d_name[0] == '.') unless -a is set
  3. In short mode: prints each filename on its own line via printf("%s\n", d_name)
  4. In long mode: calls print_long_entry() for each file

Long Format — print_long_stat()

Formats output line as:

drwxr-xr-x  2 root root  4096 Jan 15 10:30 dirname
-rw-r--r--  1 user group  1234 Jan 15 10:30 filename
  1. Permissions (mode_string()): Builds an 11-character string:
    • File type: d (dir), l (symlink), c (char device), b (block), p (fifo), s (socket), - (regular)
    • Owner: rwx (bit-tested via S_IRUSR, S_IWUSR, S_IXUSR)
    • Group: rwx (via S_IRGRP, S_IWGRP, S_IXGRP)
    • Other: rwx (via S_IROTH, S_IWOTH, S_IXOTH)
  2. Link count: st_nlink printed as %3ju
  3. Owner/Group: getpwuid(st->st_uid) and getgrgid(st->st_gid) — falls back to "?" if lookup fails
  4. Size: Raw bytes or human-readable (B/K/M/G/T/P progression with format_size())
  5. Timestamp: localtime_r(&st->st_mtime, &tmv) + strftime(timebuf, "%b %d %H:%M")

Path Handling — list_path()

Uses lstat() to check the path type:

  • Directory: calls list_dir() to list contents
  • Regular file (or other): prints the single entry directly (short or long format)

File Path Construction — print_long_entry()

Constructs full path via snprintf(fullpath, "%s/%s", path, name) (4096-byte buffer, checks truncation), then calls lstat() and print_long_stat().

Usage

onetool ls [options] [path...]

Options:
  -a, --all     show hidden files (dotfiles)
  -l, --long    long listing (permissions, owner, size, date)
  -h, --human   human readable sizes (with -l)
  --help        show help

If no path is given, lists the current directory (".").
Multiple paths are supported.

Examples

$ onetool ls
file1.txt
file2.txt
mydir

$ onetool ls -la
total 0
drwxr-xr-x  2 user group  4096 Jan 15 10:30 .
drwxr-xr-x  3 user group  4096 Jan 15 10:30 ..
-rw-r--r--  1 user group   234 Jan 15 10:30 file1.txt
-rw-r--r--  1 user group  1234 Jan 15 10:30 file2.txt
drwxr-xr-x  2 user group  4096 Jan 15 10:30 mydir

$ onetool ls -lh /bin/bash
-rwxr-xr-x  1 root root  1.4M Jan 15 10:30 /bin/bash

Limitations

  • No sorting: Entries are printed in readdir() order (filesystem-dependent, typically hash table order)
  • No color: No type-based coloring (unlike GNU ls with --color)
  • Single-column: Short format prints one entry per line (no column alignment)
  • No recursive: -R is not implemented
