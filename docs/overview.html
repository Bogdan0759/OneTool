OneTool — Project Overview

Version: 1.3.2

License: MPL-2.0 (core), BSD-2-Clause (mofl/)

Language: C (C11), with YAP and brainfuck language implementations

What is OneTool?

OneTool is a single static Linux ELF binary that bundles dozens of system tools into one executable. Instead of maintaining separate binaries for every utility (like the classic Unix toolbox), OneTool compiles everything into onetool — a single CLI entry point.

The core design principle: one executable, one CLI entry point, many capabilities implemented from scratch inside the project.

Architecture

Tool Registry

The tool_registry.h header defines the plugin-style API used by every tool:

typedef int (*onetool_entry_fn)(int argc, char *argv[]);

enum onetool_argv0_mode {
    ONETOOL_ARGV0_TOOL_NAME = 0,   // argv[0] = tool name
    ONETOOL_ARGV0_BINARY_PATH = 1, // argv[0] = binary path
};

struct onetool_tool {
    const char *name;          // Tool name (e.g. "ping")
    onetool_entry_fn entry;      // Entry function
    const char *description;    // Human-readable description
    enum onetool_argv0_mode argv0_mode;
};

Dispatcher Flow

  1. main() receives argc/argv
  2. If the first argument is "tui", it launches the TUI
  3. Otherwise it parses global flags like -to fd/path for output redirection
  4. It calls onetool_find_tool(name) which does a linear search over built-in and extra tools
  5. Found tool executes via onetool_run_tool() which sets argv[0] based on argv0_mode and calls the entry point
  6. Unknown tool names print help and return error

Extensibility

Tools can be added at build time without editing main.c by adding a line to config/extra_tools.manifest:

name|source|description|argv0_mode|extra_cflags
yap|mofl/languages/yap/yap.c|YAP language interpreter|tool|

The build system renames main() to a unique symbol automatically, compiles the source, and registers it into the tool table.

Version Counting

The version string follows the format x.r.f:

  • x — bumped when r > 9
  • r — global update or new tool
  • f — small update or bug fix

Build System

Requirements: clang, make. A custom build tool called lmake (implemented in Zig) is also bundled. Building produces the onetool static binary.

Build Steps

  1. Compile shared libraries: libs/TUI/ (ncurses wrapper), libs/elf/ (ELF64 parser), libs/memory/ (checked allocators), libs/net/ (HTTP, URL, TCP/TLS transport)
  2. Compile all built-in tools from tools/ — each tool's main() becomes a named entry point
  3. Run tools/dev/build_extra_tools.sh — reads config/extra_tools.manifest, compiles each extra tool with -Dmain= flag, automatically registering them
  4. Link everything into a single static ELF64 x86-64 executable

The result is a monolithic binary with no external runtime dependencies beyond Linux syscalls and libc.

Memory Management

The project uses checked allocation wrappers from libs/memory:

  • ot_xmalloc() — malloc with NULL check
  • ot_xcalloc() — calloc with NULL check
  • ot_xrealloc() — realloc with NULL check
  • ot_xreallocarray() — reallocarray with overflow check
  • ot_xstrdup() — strdup with NULL check
  • ot_xstrndup() — strndup with NULL check

All functions abort (exit) on allocation failure — safe for system tools.
