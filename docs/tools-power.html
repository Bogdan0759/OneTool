OneTool — Power Management Tools

The power management subsystem consists of two minimal tools for system reboot and shutdown. Both are implemented in a single C file each (~50 lines) and use the reboot() Linux syscall directly — no systemctl, shutdown, or external process spawning.

reboot — Reboot System

Source: tools/power/reboot.c (46 lines)

Entry: rb()

Reboots the system immediately or after a configurable delay. Uses the reboot() system call with LINUX_REBOOT_CMD_RESTART.

Implementation Details

  1. Argument parsing: Accepts an optional -t seconds flag. The value is parsed with strtol() — includes validation for: no characters consumed (end == argv[2]), trailing garbage (*end != '\0'), negative values, and values exceeding INT32_MAX (2,147,483,647 seconds ≈ 68 years).
  2. Delay: If a delay was specified, calls sleep(delay) before proceeding.
  3. sync(): Calls sync() to flush filesystem buffers before triggering the reboot — critical for data integrity.
  4. Syscall: Calls reboot(LINUX_REBOOT_CMD_RESTART) which sends the magic shutdown sequence 0xfee1dead + 672274793 to the kernel via the __NR_reboot syscall. On error, prints the errno string via strerror(errno) and returns 1.

Error handling: Prints invalid timer value: for bad formats, timer value is too large for overflow, and reboot failed: if the syscall fails (typically due to missing CAP_SYS_BOOT capability).

Usage

onetool reboot [-t seconds]
OptionDescription
-t secondsWait the specified number of seconds before rebooting

Examples

# Reboot immediately
onetool reboot

# Reboot after 5 seconds
onetool reboot -t 5

Note: Requires CAP_SYS_BOOT (typically root). The delay is a simple sleep() — it blocks the process before the reboot syscall.

shutdown — Power Off System

Source: tools/power/shutdown.c (46 lines)

Entry: sd()

Powers off the system immediately or after a configurable delay. Uses the reboot() system call with LINUX_REBOOT_CMD_POWER_OFF.

Implementation Details

Structurally identical to reboot.c except:

  • Syscall: Uses LINUX_REBOOT_CMD_POWER_OFF instead of LINUX_REBOOT_CMD_RESTART. This triggers kernel shutdown sequence that ACPI power-off on supported hardware.
  • Error message: Prints shutdown failed: instead of reboot failed.
  • Argument parsing: Same strtol-based parsing with full validation — identical to reboot.

Usage

onetool shutdown [-t seconds]
OptionDescription
-t secondsWait the specified number of seconds before shutting down

Examples

# Shut down immediately
onetool shutdown

# Shut down after 10 seconds
onetool shutdown -t 10

Note: Requires CAP_SYS_BOOT (typically root). On systems without ACPI or virtual machines without proper power-off support, the kernel may hang after printing "Power down."

Common Syscall Behaviour

Both tools use the same underlying reboot() libc wrapper, which invokes the __NR_reboot syscall (169 on x86-64). The kernel requires the caller to have CAP_SYS_BOOT in the user namespace. The magic arguments to the syscall are:

ParameterValue
magic10xfee1dead
magic2672274793 (LINUX_REBOOT_MAGIC2)
cmdLINUX_REBOOT_CMD_RESTART (reboot) or LINUX_REBOOT_CMD_POWER_OFF (shutdown)
